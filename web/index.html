    Raw sensor inputs

    Raw edits apply only when you click Apply inputs. Voltages feed the ADC; pressure and temperature feed two MS5837 models. Firmware filtering and stored calibration determine the displayed values. Battery and oxygen changes can take several seconds of virtual time to settle. The oxygen input assumes the recovered 10× analog gain; a dedicated wet-sensor input is unverified, but pressure changes can exercise the firmware's dive detection.

    Sensor numbers are the firmware's, which are the reverse of the engine's input names in inputs.json: sensor 1 is the MS5837 on I2C2 (pressure2Mbar, temperature2C) and sensor 2 the one on I2C1 (pressure1Mbar, temperature1C). The basic view uses the same numbers.

    A fresh profile starts with both batteries at 4100 mV, which suits the Li-Ion 3.7V-18650 type. The firmware compares the voltage with the type chosen in its battery wizard: after choosing Alkaline set about 1500 mV here, otherwise the next start shows "Change battery" and the unit goes to standby.

    Boards, CAN link and serial number

    Restart and cold boot preserve EEPROM and log storage. The default boot models a handset wake from standby; Cold boot pauses when the firmware requests standby.

    Cold boot: the firmware clears the oxygen-cell calibration (flags 0x09 back to 0x01). Calibrate again afterwards: Menu → Calibration → Air → Auto → Start → Save.

    Profile and evidence

    The profile is the emulated device's nonvolatile state of this firmware release: EEPROM (eeprom.bin), log flash (nor.ngc), the RTC checkpoint (rtc-state.json), the sensor inputs (inputs.json) and the LED color labels (led-colors.json). It is kept in this browser (a separate profile for each release) and restored on the next start. The clock advances in virtual time only, so it stands still while the emulator is closed or paused. Save evidence downloads a zip with state.json, lcd.png and can-trace.tsv (CAN trace only in dual mode).
