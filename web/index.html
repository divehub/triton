    Start options

    A cold boot makes the firmware clear the oxygen-cell calibration (flags 0x09 back to 0x01). Calibrate again afterwards: Menu → Calibration → Air → Auto → Start → Save.

    A cold boot of a custom build needs the engine to recognize the build's standby request from the hardware state; when it cannot, it refuses the boot and says why.

    Remembering files is unavailable here: this browser or mode does not provide the origin-private file system.

    Provide both firmware files to continue.

    Start game needs both boards, because the game drives the main board's pressure and oxygen inputs. Choose "Main 5.8 + handset 65.3 over CAN" under Start options.

    • This is a functional model, not a claim of physical accuracy. It is a new engine ported from the behavior of Renode 1.17.0; results from the Renode setup do not transfer automatically, and every capture is labeled with the engine that produced it.
    • Power, standby, reset, CAN wire timing, sensors and the display are simulated with explicit fixtures, named under Start options and in Advanced once the emulator runs.
    • The firmware is not part of this page. Choose your two original S-record files, both from the same release (TRITON or NEPTUN), or load them from URLs; they are checked in your browser by SHA-256 and content, and never uploaded.
    • The firmware is not part of this page. Your custom builds are checked in your browser (S-record syntax, address range, vector table) and never uploaded. Diagnostics that read the original firmware's RAM (battery readiness, decompression state) are reported as unknown for them.
    • Start game opens a dive game on the same session (same firmware, profile and start options): the depth you dive and the gas in the loop become the emulated pressure and oxygen-cell inputs, and you operate the handset through its display. The game runs on a desktop-size window and fixes its oxygen-cell voltages as a labeled game fixture.

    Inspect raw readings, command history and emulator diagnostics.

    Raw sensor inputs

    Raw edits apply only when you click Apply inputs. Voltages feed the ADC; pressure and temperature feed two MS5837 models. Firmware filtering and stored calibration determine the displayed values. Battery and oxygen changes can take several seconds of virtual time to settle. The oxygen input assumes the recovered 10× analog gain; a dedicated wet-sensor input is unverified, but pressure changes can exercise the firmware's dive detection.

    Sensor numbers are the firmware's, which are the reverse of the engine's input names in inputs.json: sensor 1 is the MS5837 on I2C2 (pressure2Mbar, temperature2C) and sensor 2 the one on I2C1 (pressure1Mbar, temperature1C). The basic view uses the same numbers.

    A fresh profile starts with both batteries at 4100 mV, which suits the Li-Ion 3.7V-18650 type. The firmware compares the voltage with the type chosen in its battery wizard: after choosing Alkaline set about 1500 mV here, otherwise the next start shows "Change battery" and the unit goes to standby.

    Boards, CAN link and serial number

    Restart and cold boot preserve EEPROM and log storage. The default boot models a handset wake from standby; Cold boot pauses when the firmware requests standby.

    Cold boot: the firmware clears the oxygen-cell calibration (flags 0x09 back to 0x01). Calibrate again afterwards: Menu → Calibration → Air → Auto → Start → Save.

    Profile and evidence

    The profile is the emulated device's nonvolatile state of this firmware release: EEPROM (eeprom.bin), log flash (nor.ngc), the RTC checkpoint (rtc-state.json), the sensor inputs (inputs.json) and the LED color labels (led-colors.json). It is kept in this browser (a separate profile for each release, and one of its own shared by every custom build) and restored on the next start. The clock advances in virtual time only, so it stands still while the emulator is closed or paused. Save evidence downloads a zip with state.json, lcd.png and can-trace.tsv (CAN trace only in dual mode).

    Game assumptions

    SL = liters at surface pressure (1.01325 bar). An adjustable power-injection setting, 100 SL/min by default (about 1.7 SL/s). CMF exactly offsets consumption. No gas supply limit.

    Oxygen-cell fixture (a game fixture, not a physical cell). Each cell reads 12 mV in air at the surface plus its own deviation of up to ±1.0 mV, drawn once for this profile and kept in this browser; resetting the profile draws new ones, so a calibration stays valid across sessions.

    Depth sets both pressure inputs: the session's surface pressure plus EN13319 water (1020 kg/m³). The temperature keeps the emulator's setting. A functional model, not a claim of physical accuracy.
